# iRent 智能車況管家：AI 引導還車拍照與取車確認 Demo

> **還車照，就是下一位的取車標準。**
> 用 AI 在拍照當下把關照片品質，讓前一位用戶的還車照直接成為下一位用戶的取車基準，車損和髒污分得清是誰造成的。

**🔗 線上 Demo：<https://ravenabalos-web.github.io/irent---demo/>**（請用手機的 Chrome 或 Safari 開啟）

> ⚠️ 本專案為 **HoTai Hackathon** 參賽作品的概念驗證（Proof of Concept），**非 iRent 官方服務**，與和泰集團及 iRent 無任何官方關聯。畫面風格參考 iRent APP 以利評審理解情境。

**English summary**: A browser-based prototype for a car/scooter-sharing service. It guides the renter to photograph the vehicle at return time (on-device object detection, live framing guidance, auto burst capture, plate OCR, item-left-behind detection) and reuses those photos as the next renter's pickup baseline, so new damage can be attributed fairly. Everything runs on the phone; no photo leaves the device.

## 要解決的問題

| 問題 | 現況 |
|---|---|
| **照片好壞要等出事才知道** | 照片模糊、漏拍、拍錯部位，往往一個多月後要求償時才發現不能用，那時已無法重拍 |
| **分不清車損是誰造成** | 取車可以略過拍照，取車照片也沒有和前一位的還車照配對，用戶無法自證 |
| **後台靠人力逐張看照片** | 所有照片都要人工檢查，異常常等到下一位用戶發現才知道 |
| **車內髒亂無法歸屬** | 取車時不拍車內，想回報髒污又怕回報錯人 |

我們分析了主辦單位提供的照片上傳清單（27,367 張照片、4,820 筆訂單），發現：

- **約 33% 的訂單缺少必拍部位**，其中約 25% 缺的是車尾兩角（左後、右後）。同一台車有時拍、有時漏拍，顯示是用戶提早按「完成」，而不是系統設定問題。
- **約 53% 的還車發生在晚上**（18:00–05:59），低光環境必須是主要設計條件。
- **同一台車、同一天連續兩次租用的配對有 1,699 組**，間隔中位數約 5.5 小時。代表「前一位的還車照當下一位的取車標準」不需要新的資料來源。

## 解決方案概覽

```
前一位用戶還車 ──► AI 把關照片品質 ──► 照片成為標準照 ──► 下一位用戶取車：看一眼確認
      ▲                                                              │
      └──────────── 下一位還車時，新的照片又成為再下一位的標準 ◄─────────┘
```

三個設計原則：

1. **拍照當下就把關**：照片不合格當場重拍，不等出事才發現。
2. **還車照就是下一位的取車標準**：每次租用都有前後可比對的照片，又不增加取車負擔。
3. **AI 標記，人員確認**：AI 只負責找出可能的問題，扣分、收費、求償一律由人員確認。

## Demo 功能

### 1. 還車：AI 引導拍攝

| 功能 | 說明 |
|---|---|
| 固定取景框 | 畫面中央固定取景框，只辨識框內的車，不會被背景的車輛或金屬物帶走 |
| 即時指令 | 依偏移量顯示長短不同的方向箭頭，加上「太遠／剛好／太近」距離條；文字與語音分「多一些」「一點點」 |
| 自動連拍 | 條件全部符合時取景框變綠色，自動連拍 5 張並挑出最清楚的一張；保留手動快門 |
| 防手震 | 用手機陀螺儀判斷晃動；短暫晃一下只會讓進度慢慢回退，不會歸零 |
| 換角判斷 | 用方向感測器確認用戶真的順時針走到下一個角，走反或走過頭會提醒 |
| 車牌比對 | 拍車尾時用 OCR 讀車牌，和訂單車號比對；讀到別台車的車牌會擋下，防止拍別台車充數 |
| 方位推斷 | 機車只有車尾有車牌，拍「車頭」的角卻讀到車牌時，判定為拍錯方向 |
| 腳踏板／車內 | 四角之後拍腳踏板（汽車拍車內），AI 偵測杯子、瓶子等遺留物，並分為乾淨、普通、髒污 |
| 照片燈號 | 🟢 合格，不需人工查看；🟡 待人工確認（不得用來處罰用戶）；🔴 不合格，必須重拍 |
| 數位指紋 | 每張照片計算 SHA-256，證明照片拍下後沒有被修改 |
| 還車回條 | 證明「我的責任在這個時間點結束」 |

### 2. 取車：看一眼確認

- 一頁列出前一位用戶的 5 張還車照（四角＋腳踏板），點照片可放大。
- 每項按「**相符**」或「**不一樣**」，全部選完才能確認取車。
- 按「不一樣」→ 拍下差異處 → 選擇類型（刮痕、凹陷、髒污、遺留物、其他）。
- **腳踏板由 AI 比對前後兩張照片**，列出比標準照多出來的物品。
- 提示「標準照片中看得到的損傷，不會算在您身上」。

### 3. 後台

- **還車照片審核清單**：依燈號分流，只需人工查看黃燈照片，並列出黃燈原因、車牌比對結果、整潔分類。
- **取車回報**：標準照與回報照片並排，依標準照燈號標示責任歸屬：
  - 標準照為綠燈 → 若確認為新損傷，歸為無人租用期間，由營運方吸收。
  - 標準照為黃燈 → 屬前一位或無人租用期間，由人員調查。

## 使用流程

> Demo 資料只存在本次開啟的網頁中。**請先還車、再取車，全程不要重新整理或關閉分頁**，也盡量不要切換到其他 App（iPhone 可能會自動重新載入網頁）。

1. 用手機開啟 Demo 網址，允許相機權限。iPhone 也請允許「動作與方向」。
2. 首頁點「**還車**」。
3. 輸入**模擬訂單車號**（正式版由訂單自動帶入；留空則略過車牌比對），選擇車種，按「開始還車拍照」。
   - 第一次開啟需下載 AI 模型，約 5–15 秒；之後會從手機直接載入。
4. 站在車輛**左前方**，把車放進取景框，照箭頭與距離條調整，框變綠色就會自動連拍。
5. 確認照片與燈號，按「完成此部位」；順時針依序拍**右前 → 右後 → 左後**。
6. 最後拍**腳踏板**（汽車拍車內）。
7. 查看「**還車回條**」與「**後台審核**」。
8. 點「**回首頁，換下一位取車**」，再點「**取車**」。
9. 逐項按「相符」或「不一樣」，最後按「**確認取車**」，切到「後台：取車回報」查看結果。

## 測試小技巧

| 情境 | 建議 |
|---|---|
| 手邊沒有車，用螢幕上的照片測試 | 拍照畫面右上角「調整」→ 關閉「用方向感測器判斷是否已換角」，否則人沒移動，第二張之後會一直要求換角 |
| 一直不自動拍 | 打開「調整」看即時數值，找出沒過的條件，並可調整亮度、清晰度、晃動、轉動角度的門檻 |
| 想展示遺留物偵測 | 還車時在腳踏板放一個杯子；取車時再多放一個，按「不一樣」拍下，AI 會列出多出來的那一個 |
| 想展示車牌防呆 | 訂單車號輸入一個不同的號碼，拍車尾時會亮紅燈 |
| 第一次載入很久 | 示範前先用同一支手機、同一個瀏覽器開過一次，讓模型存進手機 |

## 技術架構與運作原理

整個 Demo 是**單一 HTML 檔案**，部署在 GitHub Pages，**所有運算都在手機瀏覽器內完成**，沒有後端伺服器，照片不會上傳。

```
相機畫面（每 0.1 秒）
   │
   ▼
COCO-SSD 物件偵測（TensorFlow.js，預訓練模型，免訓練）
   │  回傳：機車／汽車／杯子……的位置與信心分數
   ▼
規則判斷 ── 置中、距離、亮度、清晰度、晃動、換角方向
   │
   ▼
條件持續符合 → 自動連拍 5 張 → 挑最清楚的一張
   │
   ├─► SHA-256 數位指紋
   ├─► Tesseract.js 讀車牌 → 與訂單車號比對
   ├─► 遺留物偵測 → 整潔分類
   └─► 燈號（規則判定）→ 回條／後台／取車標準照
```

| 項目 | 做法 |
|---|---|
| 車輛與物品偵測 | COCO-SSD（lite_mobilenet_v2）on TensorFlow.js。COCO 資料集本身包含機車、汽車、杯子、瓶子等類別，**不需要自行訓練** |
| 亮度 | 取景範圍轉灰階後的平均亮度 |
| 清晰度 | 拉普拉斯變異數（Variance of Laplacian），清楚的照片邊緣分明、數值較大 |
| 晃動 | DeviceMotion 陀螺儀轉速；不支援時改看偵測框的位移 |
| 換角方向 | DeviceOrientation 推算鏡頭朝向，順時針每走一角約 +90° |
| 車牌辨識 | Tesseract.js，限定英數字，容許 1 個字的誤差，可處理被拆成兩段的車牌 |
| 數位指紋 | Web Crypto API（SHA-256） |
| 模型快取 | 第一次下載後存入瀏覽器 IndexedDB |

**AI 只負責「看見」，判斷交給規則。** 模型只回答「畫面裡有什麼、在哪裡」，要不要拍、燈號、評語都由可解釋的規則決定。照片是證據，判斷過程必須說得清楚；門檻也能現場調整，不必重新訓練模型。

## 設計決策

- **只在拍攝前提升品質，不用 AI 修圖**：照片是證據，修過的照片證據力會被質疑。生成式 AI 可能抹掉真的刮痕或補出不存在的痕跡。原始照片一律不修改，遺留物的標註只畫在另一份副本上。
- **黃燈不得用來處罰用戶**：黃燈只代表這張照片的證據力需要人工確認，不代表用戶有錯。
- **讀不到車牌不擋人**：OCR 本來就會失手，不能因為 AI 讀不到就懲罰用戶；只有清楚讀到別台車的車牌才擋下。
- **取車用戶看不到 AI 燈號**：AI 結果只給後台參考，避免被誤認為正式判定。
- **取車不提供「全部相符」一鍵按鈕**：讓用戶每一項至少看一眼。
- **固定取景框取代追蹤框**：第一版的偵測框會跟著車亂跳，實測後改成用戶把車放進固定框，操作直覺很多。

## 限制與尚未實作

- **部位辨識**：目前以順序引導、方向感測器與車牌推斷方位，**機車的左前與右前仍可能搞混**。正式版需用營運照片訓練部位辨識模型。
- **車損偵測與前後比對**：需要訓練車損偵測模型（例如以公開車損資料集訓練再微調），本 Demo 尚未包含；目前只有腳踏板的遺留物能做 AI 前後比對。
- **遺留物偵測範圍**：只認得 COCO 學過的物品（杯子、瓶子、袋子、食物等），紙屑、菸蒂、污漬認不出來。
- **車牌 OCR**：對斜拍、反光、夜間的辨識率尚未以真實車牌驗證。
- **輕量模型**：為了在手機上即時運算，暗處或車輛只露出一部分時較容易鎖定失敗。
- **資料保存**：Demo 沒有後端，資料只存在本次開啟的網頁中，無法跨裝置。正式版應上傳至雲端不可修改的儲存空間。
- **提案中尚未納入 Demo 的功能**：其他車損補拍、停車位置、邊拍邊傳與無訊號暫存、還車後有人動過車的重拍規則、黃燈部位補拍、標準照背景模糊、異味回報、事故處理引導。

## 版本紀錄

| 版本 | 重點 |
|---|---|
| v1 | COCO-SSD 鎖定車輛、規則判斷、自動拍攝、燈號、還車回條、後台清單 |
| v2 | 依實測回饋改版：固定取景框、方向箭頭與距離條、陀螺儀防手震、連拍挑最清楚、車牌比對、換角方向判斷、模型存手機 |
| v3 | 新增腳踏板／車內拍攝與遺留物偵測、整潔分類 |
| v4 | 新增首頁與取車確認流程、取車差異回報、後台責任歸屬 |

**v1 實測回饋 → v2 的修改**

| 實測發現的問題 | v2 的改法 |
|---|---|
| 偵測框會亂跑，很難靠追框找車 | 改為固定取景框，只認框內的車 |
| 背景有其他車或金屬物時框會跳走 | 忽略框外物體，並平滑處理偵測框 |
| 指令只說「往右」，不知道要往右多少 | 箭頭長度與語音分程度，加上距離條 |
| 等待拍攝時一抖就失敗 | 改用陀螺儀判斷晃動，進度慢慢回退，並改為連拍 |
| 方位誤判 | 加入換角方向判斷與車牌推斷方位 |

## 隱私

- 所有辨識都在手機上進行，**照片不會上傳到任何伺服器**，關閉頁面即清除。
- 本 Repo **不包含**主辦單位提供的任何照片或原始資料；文中的統計數字為彙總結果。
- 正式版設計（未於 Demo 實作）：只能用 APP 內相機拍攝、以手機安全晶片加上數位簽章、以伺服器時間為準、給其他用戶看的照片會模糊路人臉孔與他車車牌。
